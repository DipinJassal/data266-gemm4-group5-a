**What changed:** `prompts/system.md` only: one added "Time Budget" section (call the free `get_status()` first and then every 8 tool calls; if more than half the time is used with no source edit, apply the best-supported fix; under 60 s left, start nothing new and call `submit_patch`; never make arbitrary edits to beat the deadline). Everything else, including `eval_config.yaml` (4.5 min / 50 tool calls / 50 turns), is copied unchanged from `dipin-step-budget-v1`, which is the control.
**Why:** targets sessions that run out of time before a usable source edit. In the control's smoke run (RUN-006, internal evidence, not published research) 9/10 sessions hit the time limit, 5/10 timed out with no successful source edit, and the agent called `get_status()` once in 10 tasks; the harness warns only about tool calls (at ≤10 remaining), never about wall-clock time.
**Source:** [4] Song et al., SWE-Master (arXiv:2602.03411), Sec. 3.4.3 "Budget Awareness": during RL training the environment tells the agent its remaining turn budget each turn, to encourage "more deliberate planning and earlier convergence toward a viable solution"; Sec. 3.4.2 reports that unsubmitted trajectories often stem from redundant verification loops. Our adaptation (wall-clock budget, read by the agent via `get_status()`, prompt only, no training) is not taken from the paper.
