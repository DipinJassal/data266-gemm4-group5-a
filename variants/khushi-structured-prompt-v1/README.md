**What changed:** `prompts/system.md` only: structured-loop prompt (reproduce when cheap, localize, plan, edit, targeted test, pre-submit checklist, submit; first edit within about 10 tool calls); everything else, including `eval_config.yaml` (4.5 min / 50 tool calls), is copied unchanged from `dipin-step-budget-v1`, which is the control, so the comparison isolates the prompt from the budget.
**Why:** targets empty diffs (20/30 baseline dev, 3/10 V2 smoke) and wrong patches (8/30 baseline dev) by encouraging an earlier edit, root-cause reasoning, targeted verification and a valid non-empty patch; figures are repo-reported in CLAUDE.md, not independently verified.
**Source:** [11] Jiang, Lo and Liu (arXiv:2512.22256), Sec. 2.1 and 5.1.1: issue resolution as localization, repair, patch validation (incl. reproduction tests) and selection, run as logical phases not a fixed order; pipelines suit tight budgets or weaker backbones. Our reproduce/plan/checklist steps are an adaptation, not taken from the paper.
